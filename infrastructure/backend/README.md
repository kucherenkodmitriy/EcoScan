# Backend Infrastructure

This directory contains the Infrastructure as Code (IaC) for the EcoScan backend, which is deployed as a unified CloudFormation stack using AWS SAM. It defines the API Gateway, the Lambda function integration for the `bin-status-reporter` service, and all related IAM roles and permissions.

## Files

- `template.yaml`: The primary AWS SAM template that defines the backend resources.
- `openapi.yaml`: An OpenAPI 3.0 specification that defines the API endpoints, request/response schemas, and validation rules. This file is referenced by `template.yaml` to configure the API Gateway.
- `deploy.sh`: A comprehensive deployment script that automates the entire build and deployment process.
- `packaged.yaml`: An auto-generated template created by the `sam package` command during deployment. **Do not edit this file manually.**

## API Endpoints

The API is defined in `openapi.yaml` and exposes the following endpoint:

### Update Bin Status
- **Path**: `/bins/{binId}/status`
- **Method**: `PUT`
- **Description**: Updates the status of a specific trash bin.
- **Request Body**:
  ```json
  {
    "status": {
      "value": 7
    }
  }
  ```
  The `value` must be an integer between 0 and 10.

- **Success Response (200 OK)**:
  ```json
  {
    "success": true,
    "message": "Bin status updated to 70%",
    "updated_at": "2024-03-20T12:00:00Z"
  }
  ```

## Deployment

Deployment is fully automated via the `deploy.sh` script.

### Prerequisites

1.  **AWS CLI**: Installed and configured.
2.  **Docker**: Required for the Rust cross-compilation build process.
3.  **`.env` file**: Create a `.env` file in the project root with your AWS credentials. See the main `README.md` for the required format.

### How to Deploy

Navigate to this directory (`infrastructure/backend`) and run the deployment script:

```bash
./deploy.sh --environment <env>
```

- Replace `<env>` with the target environment (e.g., `dev`, `staging`).

The script performs the following actions:
1.  Builds the `bin-status-reporter` Rust service in a Docker container to ensure a compatible Linux binary.
2.  Packages the Lambda function and the SAM template.
3.  Uploads the deployment artifacts to the correct S3 bucket (`dev-ecoscan-lambda-deployments`).
4.  Deploys the CloudFormation stack named `dev-ecoscan-bin-status-reporter`.

### Script Options

- `--environment <env>`: (Required) The deployment environment (e.g., `dev`).
- `--region <aws-region>`: The target AWS region (defaults to `eu-central-1`).
- `--rate-limit <num>`: Sets the API Gateway rate limit (defaults to `10`).
- `--burst-limit <num>`: Sets the API Gateway burst limit (defaults to `5`).
- `--help`: Displays the help message.

## Environment Variables

The CloudFormation stack automatically configures the following environment variables for the Lambda function:

- `TRASH_BINS_TABLE`: `dev-ecoscan-trash-bins`
- `STATUS_REPORTS_TABLE`: `dev-ecoscan-status-reports`
- `LOG_LEVEL`: `INFO`

## Security & Monitoring

- **Security**: The API is protected by IAM roles, request validation, and rate limiting configured in `openapi.yaml`.
- **Monitoring**: API Gateway metrics (request counts, latency, errors) and Lambda logs are available in AWS CloudWatch.
